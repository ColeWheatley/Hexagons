Glossary — terms used below
Manifest (tile_manifest.json)
A ~95 KB JSON "table of contents": lists every terrain island and every texture page with its bounds and sizes. It's the first thing the app downloads; nothing renders without it.
Gosper island / geometry binaries (gosper_*.bin)
The unit of terrain. One island = a snowflake-shaped cluster of 16,807 small hexes (6.4 m each), stored as one ~280 KB binary file holding elevations and slopes. The current map is 197 islands around Stubai. "Matching binaries" in the Codex audit meant: the manifest lists 197 of these files but zero existed on disk — the checkout's data was from an older format.
Texture pages & tiers
The aerial photography is shipped in coarse 1024 m squares ("pages," never per terrain island). Each page has yellow 32 px WebP for transient first paint, then KTX2 low 128 px, medium 256 px, or high 4096 px. KTX2 stays GPU-compressed, so a high page costs ~7 MB of VRAM instead of ~67 MB.
Basis transcoder
A WebAssembly decoder (~a few MB of memory per copy) that converts KTX2 files into whatever compressed format the user's specific GPU speaks. Runs inside the worker threads.
Worker pool ("round-robin workers")
2–6 background browser threads that parse geometry binaries and decode textures so the main thread doesn't stutter. "Round-robin" just means jobs are dealt to them in turn — and currently each one may load its own copy of the Basis decoder.
Residency / VRAM ledger
"Residency" = which texture pages are currently held in memory. The VRAM ledger (vram_ledger.js) is the app's own bookkeeping of GPU memory use; the high tier has a 256 MB budget with least-recently-used eviction.
The peaks GeoJSON
Yes — assets/tirol_peaks.geojson is the file with the peak names: 4,368 Tirol summits with name, elevation, prominence. It's 1.73 MB and is parsed on the main thread the first time you click the search box.
DPR (devicePixelRatio)
How many physical pixels per CSS pixel. A retina laptop is 2, phones up to 3+. Rendering at DPR 3 costs ~9× the pixels of DPR 1. The app currently renders at full native DPR, uncapped.
Render-on-demand
The animation loop runs every frame but skips actually drawing when nothing changed. Saves battery — and is why the FPS readout "drops to 2–4" when idle: the counter divides rendered frames by wall-clock time.
Sintered / engine states
The app's activity ladder: MOVING (camera in motion) → SINTERING (just stopped, upgrading quality) → STATIC (settled, renders only on demand).
TTFTF
Time To First Textured Frame — from page open until the visible terrain is fully painted with real imagery. The single best first-impression metric.
Diagnostic tattoos
Colored watermarks the baker stamps onto texture tiers in dev bakes (yellow=WebP bootstrap, green=low, blue=medium, pink=high) so you can see which tier is on screen. The live beta currently shows them to the public; their stroke is now half the prior thickness.

Cole's idea. FrontendGain: high (battery, background CPU)✓ Live gate: settled/hidden 0 ticks, 0 renders

Even when the map is completely settled, the animation loop wakes up 60× per second and does real work — queue maintenance, camera math, culling checks, profiler feeding — before deciding "nothing changed" and skipping the draw. FrontendGain: high (memory + first texture)✓ Dedicated lanes, ≤2 decoders, cancellable queued work

The 2–6 background worker threads treat geometry parsing and texture decoding as interchangeable jobs dealt out in turn. Two consequences: each worker may end up loading its own multi-megabyte copy of the Basis texture decoder, and after a fast pan a burst of geometry jobs can starve texture decoding — terrain appears but stays unpainted. Dedicate one or two workers to textures with a single pre-warmed decoder, keep the rest for geometry, and let stale jobs from an abandoned view be cancelled rather than completed (view epochs / abortable jobs).

Done when: at most two decoder instances exist; peak JS heap drops measurably; under throttled load, first textured terrain improves ≥20%; a rapid pan cancels the previous view's queued jobs.
